# 🦈 Wireshark Packet Analysis: DNS (Domain Name System)

The **Domain Name System (DNS)** is an application-layer protocol running over **UDP port 53** (and **TCP port 53** for zone transfers or responses exceeding 512 bytes). It translates human-friendly domain names (e.g., `google.com`) into computer-routable IP addresses (e.g., `142.250.190.46`).

---

## 🏗️ The DNS Resolution Hierarchy

```text
                           [ Root DNS Servers "." ]
                                      │
                         [ Top-Level Domain (TLD) ]
                            (".com", ".org", ".net")
                                      │
                      [ Authoritative DNS Server ]
                            ("example.com")
                                      │
                         [ Local Recursive Resolver ]
                            ("8.8.8.8" or ISP DNS)
                                      │
                             [ Client Machine ]
```

## 🔬 DNS Packet Breakdown in Wireshark

### 1. DNS Query (Standard Query A example.com)
```text
User Datagram Protocol, Src Port: 54321, Dst Port: 53
Domain Name System (query)
    Transaction ID: 0x1a2b
    Flags: 0x0100 Standard query
        0... .... .... .... = Response: Message is a query
        .000 0... .... .... = Opcode: Standard query (0)
        .... ..1. .... .... = Recursion desired: Do query recursively
    Questions: 1
    Answer RRs: 0
    Authority RRs: 0
    Additional RRs: 0
    Queries
        example.com: type A, class IN
            Name: example.com
            Type: A (Host Address) (1)
            Class: IN (0x0001)
```

**Key Fields in Query:**
- **Transaction ID (`0x1a2b`):** A unique 16-bit identifier generated by the client. The matching response **must** contain this exact ID.
- **Flags:** `0x0100` signifies a standard query requesting recursive lookup (`RD = 1`).
- **Query Type:** `A` (IPv4 host address), `AAAA` (IPv6), `MX` (Mail Exchange), `TXT` (SPF/verification records), `CNAME` (Canonical name alias).

---

### 2. DNS Response (Standard Query Response)
```text
Domain Name System (response)
    Transaction ID: 0x1a2b    <-- Matches Query ID
    Flags: 0x8180 Standard query response, No error
        1... .... .... .... = Response: Message is a response
        .... .0.. .... .... = Authoritative: Server is not an authority for domain
        .... ...1 .... .... = Recursion desired: Do query recursively
        .... .... 1... .... = Recursion available: Server can do recursive queries
        .... .... .... 0000 = Reply code: No error (0)
    Questions: 1
    Answer RRs: 1
    Answers
        example.com: type A, class IN, TTL 3600, addr 93.184.216.34
            Name: example.com
            Type: A (Host Address) (1)
            Class: IN (0x0001)
            Time to live: 3600 (1 hour)
            Data length: 4
            Address: 93.184.216.34
```

**Key Response Flags & Codes:**
- **Reply Code (RCODE):**
  - `0 (No error)`: Successful resolution.
  - `2 (Server failure)`: Resolver encountered an internal error.
  - `3 (NXDOMAIN / Name Error)`: Domain does not exist.
  - `5 (Refused)`: Server refuses to answer query due to policy.
- **Time to Live (TTL):** Indicates how many seconds the client/resolver may cache the answer before re-querying.

## 🎯 Wireshark Display Filters for DNS

```text
# Show all DNS traffic
dns

# Show only DNS queries
dns.flags.response == 0

# Show only DNS responses
dns.flags.response == 1

# Filter by queried domain name
dns.qry.name contains "google"

# Find failed domain resolutions (NXDOMAIN)
dns.flags.rcode == 3

# Filter specific DNS record type (e.g., A record = 1, MX = 15, TXT = 16)
dns.qry.type == 1

# Inspect traffic to a specific DNS resolver (e.g. Google Public DNS)
ip.addr == 8.8.8.8 and udp.port == 53
```

## 🛡️ Cybersecurity Threats Involving DNS

1. **DNS Spoofing / Cache Poisoning:**
   - Attacker floods resolver with fraudulent responses guessing the Transaction ID and source port, corrupting the resolver's cache so users are redirected to phishing sites.
   - *Mitigation:* **DNSSEC (DNS Security Extensions)**, which cryptographically signs DNS records.

2. **DNS Tunneling & Data Exfiltration:**
   - Attackers encode stolen passwords or files into subdomains sent in DNS queries (e.g. `cGFzc3dvcmQxMjM=.attacker.com`), bypassing egress firewall restrictions.

3. **DNS Amplification (DDoS):**
   - Attacker sends small queries with `ANY` or `TXT` requests with a spoofed victim IP address to open resolvers, resulting in responses up to 50x larger overwhelming the victim's link.
